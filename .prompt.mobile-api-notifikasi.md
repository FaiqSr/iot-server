Prompt: Integrasi API & Notifikasi ke React Native (Expo)

Tujuan

- Hasilkan instruksi lengkap yang bisa ditempel ke GitHub Copilot (atau LLM serupa) di project mobile (React Native + Expo + TypeScript) untuk mengintegrasikan API server ini dan FCM topic-based notifications.

Konteks (dari repo server)

- Project server menggunakan Express + Prisma + Zod. Relevan:
  - `src/routes/routes.ts` (daftar endpoint)
  - `src/service/NotificationService.ts` (konvensi topic dan payload FCM)
  - `src/controller/NotificationController.ts` (contoh pemicu notifikasi pada pembacaan sensor)
  - `src/service/SensorSettingService.ts` (atribut model `SensorSetting` seperti `min_value`, `max_value`, `alert_interval`, `last_notified_at`)
- Mobile client: Expo + TypeScript. Untuk fungsionalitas topic subscription, prefer EAS prebuild / bare untuk menggunakan `@react-native-firebase/messaging`. Jika menggunakan managed Expo, beri alternatif dengan `expo-notifications` dan catat tradeoffs.

Input/Parameter untuk prompt ini

- `API_BASE_URL` (string): default fallback: Android emulator `http://10.0.2.2:3000`, iOS simulator `http://localhost:3000`. Harus bisa dikonfigurasi via `Constants.manifest.extra.API_BASE_URL` atau environment.
- Struktur folder mobile: `mobile/app/` (atau `app/`) dengan subfolders `services`, `screens`, `hooks`, `context`, `types`, `components`.

Scope & Deliverables (yang harus dihasilkan oleh Copilot)

Endpoint summary (gunakan path & shape ini persis)

- POST `/user/login`
  - Body: `{ email, password }`
  - Response: `{ data: { accessToken, user: { id, email, name } } }`
- GET `/api/user/devices`
  - Header: `Authorization: Bearer <token>`
  - Response: `{ data: Device[] }`
- POST `/api/claim-device`
  - Header: Authorization
  - Body: `{ idAlat: string }` (UUID)
  - Response: `{ data: Device }`
- GET `/api/settings/:alatId`
  - Response: `{ data: SensorSetting[] }`
- PATCH `/api/settings/:settingId`
  - Body: partial `{ min_value?, max_value?, is_active?, alert_interval? }`
  - Response: `{ data: SensorSetting }`

Contoh Axios instance (`app/services/api.ts`) — Copilot harus buat file ini di `app/services/`:

```ts
import axios from "axios";
import Constants from "expo-constants";
import * as SecureStore from "expo-secure-store";

const API_BASE_URL =
  (Constants.manifest as any)?.extra?.API_BASE_URL || process.env.API_BASE_URL || "http://10.0.2.2:3000";

const api = axios.create({ baseURL: API_BASE_URL, timeout: 10000 });

api.interceptors.request.use(async (config) => {
  const token = await SecureStore.getItemAsync("accessToken");
  if (token && config.headers) config.headers.Authorization = `Bearer ${token}`;
  return config;
});

export default api;
```

Contoh wrapper `app/services/sensorApi.ts` (fetch + patch) — inklusi error handler untuk server unreachable (simpan di `app/services/`):

```ts
import api from "./api";
import axios from "axios";
import { SensorSetting } from "../types/api";

function isNetworkError(err: any) {
  return axios.isAxiosError(err) && !err.response;
}

export async function getSensorSettings(alatId: string): Promise<SensorSetting[]> {
  try {
    const res = await api.get(`/api/settings/${encodeURIComponent(alatId)}`);
    return res.data.data as SensorSetting[];
  } catch (err) {
    if (isNetworkError(err)) {
      throw new Error("Server tidak terjangkau");
    }
    throw err;
  }
}

export async function updateSensorSetting(
  settingId: number,
  payload: Partial<Pick<SensorSetting, "min_value" | "max_value" | "is_active" | "alert_interval">>,
): Promise<SensorSetting> {
  try {
    const res = await api.patch(`/api/settings/${settingId}`, payload);
    return res.data.data as SensorSetting;
  } catch (err) {
    if (isNetworkError(err)) throw new Error("Server tidak terjangkau");
    throw err;
  }
}
```

Panduan integrasi FCM (topik) — isi `app/services/push.ts`:

- Rekomendasi: gunakan `@react-native-firebase/messaging` + `notifee` untuk notifikasi lokal (atau `expo-notifications` bila tetap managed).
- Copilot harus menghasilkan fungsi:
  - `initPush()` — minta permission, inisialisasi messaging, kembalikan token perangkat.
  - `getToken()` — return messaging token.
  - `subscribeToAlat(alatId)` — `messaging().subscribeToTopic('alat_' + alatId)`.
  - `unsubscribeFromAlat(alatId)`.
  - `onMessageHandler()` — register `messaging().onMessage()` untuk menampilkan notifikasi (pakai `notifee.displayNotification` atau `expo-notifications` fallback).
  - `setBackgroundHandler()` — register background handler.

Contoh ringkas (dimasukkan oleh Copilot ke `app/services/push.ts`):

```ts
import messaging from "@react-native-firebase/messaging";
import notifee from "@notifee/react-native";

export async function initPush() {
  const authStatus = await messaging().requestPermission();
  const enabled =
    authStatus === messaging.AuthorizationStatus.AUTHORIZED || authStatus === messaging.AuthorizationStatus.PROVISIONAL;
  if (!enabled) return null;
  const token = await messaging().getToken();
  messaging().onMessage(async (remoteMessage) => {
    await notifee.displayNotification({
      title: remoteMessage.notification?.title,
      body: remoteMessage.notification?.body,
    });
  });
  messaging().setBackgroundMessageHandler(async (remoteMessage) => {
    /* background display handled by OS */
  });
  return token;
}

export function subscribeToAlat(alatId: string) {
  return messaging().subscribeToTopic(`alat_${alatId}`);
}
export function unsubscribeFromAlat(alatId: string) {
  return messaging().unsubscribeFromTopic(`alat_${alatId}`);
}
```

Important notes untuk Copilot (harus di-dokumentasikan dalam README):

- Jika memilih managed Expo + `expo-notifications`, server-side payloads mungkin perlu penyesuaian karena `expo-notifications` menggunakan FCM token registration tanpa topik sama seperti firebase-admin. Berikan opsi implementasi token-register endpoint di server sebagai alternatif.
- Dokumentasikan langkah pembuatan Firebase project, download `google-services.json` (Android) dan `GoogleService-Info.plist` (iOS), dan langkah EAS/prebuild required.

Error handling & UX expectations (harus di-implement oleh Copilot)

- Jika server unreachable (network error / timeout): tampilkan toast "Server tidak terjangkau" dan tombol retry.
- Jika response 401: bersihkan token (SecureStore.deleteItemAsync('accessToken')) dan arahkan ke Login.
- Validasi input sebelum `PATCH`: pastikan `min_value`/`max_value` numeric dan pH range 0-14 bila sensor_type adalah PH.

Acceptance criteria (untuk QA)

- Login -> token tersimpan di SecureStore.
- Devices screen memanggil `/api/user/devices` dan menampilkan list.
- Claim device memanggil `/api/claim-device` dan pada sukses memanggil `subscribeToAlat(<id>)`.
- Settings screen memuat `GET /api/settings/:alatId` dan dapat `PATCH` setting (UI menampilkan validasi dan error jika server unreachable).
- Firebase topic notifications diterima di foreground/background setelah subscribe (uji via Firebase Console topic messaging ke `alat_<id>`).
